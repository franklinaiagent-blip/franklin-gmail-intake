Franklin Gmail Intake

Privacy notice

Franklin Gmail Intake is a private, operator-managed evidence-intake tool operated by Mark McDonald.

Access and information collected

With the account holder's Google authorisation, the application requests only gmail.readonly. This is mailbox-wide read permission: Google does not offer an Inbox-only or label-only scope. The application selects a configured intake Inbox and, for a separate account, a designated label. The label adapter checks message membership. Account identity and label metadata may be read to validate these sources.

Imported data includes raw emails, sender and recipient details, subjects, bodies, dates, headers, message and thread identifiers, forwarded context, attachments and inline MIME content. Records also include file metadata, deduplication hashes, classification, storage locations, processing status and errors. Baseline operations can record identifiers without importing bodies.

The intake cannot send, delete, archive, relabel or mark emails read. It uses Google OAuth; this site does not collect Gmail passwords.

Purpose and processing

Data is used to preserve evidence, organise and retrieve documents, track provenance, avoid duplicates and flag review items. Intake uses deterministic classification. Relevant messages and substantive attachments are routed to designated local evidence folders. Decorative inline content remains in source evidence; uncertain items remain for review. Potential document-index references are queued locally. Automatic intake writes to Franklin HQ are disabled pending an approved provenance mechanism; email does not automatically create tasks, projects or decisions.

Storage, access and sharing

Raw messages, attachments, manifests and a SQLite ledger are stored on the operator's computer. OAuth credentials and tokens are stored separately in owner-only local files. The scripts also apply restrictive permissions to evidence files and the ledger. These are filesystem controls, not a claim of application-level encryption.

The intake scripts retrieve data from Google and process it locally. Routed evidence is available to the operator and authorised assistant workflows. Subsequent assistant analysis may transmit relevant content to the AI service configured for that workflow. Local storage does not guarantee that all subsequent processing stays on the device.

The intake implementation does not sell data, use it for advertising or train general-purpose AI models. Use or transfer of Google API data must comply with the Google API Services User Data Policy, including Limited Use requirements.

Retention, revocation and deletion

There is no automatic retention-expiry or deletion schedule. Imported evidence remains until the operator removes it. Revoke access through Google Account connections to prevent future authorised retrieval. Revocation does not erase existing copies.

Contact the operator for access or deletion requests. Deletion requires review of raw evidence, attachments, routed copies, manifests, database records, logs and applicable backups. The operator will explain any applicable retention requirement.

This website

This public site contains only a homepage and privacy notice, not Gmail credentials, messages or attachments. It has no Gmail login, forms, application-added analytics or advertising trackers. GitHub Pages may process technical visitor data such as IP addresses and request logs under GitHub's privacy statement.
